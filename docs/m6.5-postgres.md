## Phase 0 — prove CloudNativePG can back up to R2

**Why first:** it is the only assumption in the plan that could invalidate the plan. R2 is
S3-compatible and CNPG's barman-cloud backend targets S3-compatible storage, but that pairing is
unproven here and R2 has known rough edges around multipart uploads and checksum headers. Finding
this out after the provider swap would be the expensive ordering.

**Work:** throwaway CNPG install in the `dev` vcluster. One small cluster, an R2 bucket with a
scoped API token, `barmanObjectStore` configured against the R2 endpoint. Force a base backup.
Force WAL archiving. Then delete the cluster and restore it from the R2 backup alone.

**Gate:** a restored cluster containing a row written before the backup. Not "the backup command
exited 0" — a restore.

**If it fails:** in order of preference — different S3-compatible target (Backblaze B2, or real
S3, both cheap at this size); WAL-G or pgBackRest driven by a sidecar instead of CNPG's built-in;
or fall back to the self-hosted-MySQL option recorded as the rejected-but-kept alternative. Do
not proceed into Phase 2 with backups unsolved.

**Leaves behind:** nothing. Tear it down. The real thing is built by Terraform in Phase 1.

**What actually happened:** Phase 0 was skipped. The real layer was written on 2026-09-06 and
applied on 2026-09-27 before anything proved a restore. The gate was then run against the real
dev Cluster, which was cheap because it held no data, and it **passed**, more strongly than
written. A row from before the base backup **and** a row that existed only in archived WAL
both came back in a Cluster built from R2 alone. 53 seconds to healthy. No R2 multipart or
checksum trouble appeared. Procedure and gotchas: `docs/homelab-infra/architecture.md` →
Restoring.

The skip did cost something. The broken plugin certificates (below) would have shown up in a
spike, not on the first real apply.

## Phase 1 — Postgres on the platform (`homelab-infra`)

> **As built (2026-09-06 / 09-27), superseding parts of the plan below.** Reasoning in
> `homelab-infra/decisions.md`.
> - The operator is **not** in `10-host`. A CRD on the host k3s is invisible inside the
>   vclusters. It runs inside each vcluster, installed by a new `15-databases` layer.
> - The Cluster lives in a shared **`data`** namespace, not in `secret-santa`, and is created by
>   `15-databases`, not the tenant module. The NetworkPolicy is therefore cross-namespace: it
>   allows `secret-santa` → the cluster's pods on 5432. The plan's "nothing outside the
>   namespace" became "nothing but the app's namespace".
> - Backups use the **Barman Cloud plugin**. The in-tree `barmanObjectStore` named below is
>   deprecated and removed in CNPG 1.31.
> - The quota concern was handled by giving `data` its own quota (2 CPU, 2Gi). The tenant quota
>   was never touched.
> - The connection string is generated by `15-databases` and merged into `secret-santa-config`
>   by `20-tenants`. It's no longer a hand-typed variable.
> - Postgres is **18.4**. The R2 bucket is in `00-cloudflare`, with its key made by hand.
> - **The first apply didn't produce a database.** The Barman plugin's mTLS certificates were
>   CA-signed, but both ends pin the exact certificate. Fixed by homelab-infra PR #4.

**Work (as originally planned):**
- CNPG operator into `10-host` as a Helm release, alongside the existing platform components.
- A Postgres `Cluster` per tenant environment (`dev`, `prod`) — created by the tenant module in
  `20-tenants`, not by `deploy/`. Single instance; this is a single-node cluster and pretending
  otherwise buys nothing.
- Storage: `local-path` PVC. Size it generously — this dataset is small and resizing a PVC on
  `local-path` is unpleasant.
- Credentials generated by Terraform into the existing `app_config` secret, consistent with the
  2026-09-03 decision that application secrets live in Terraform state. The connection string
  replaces `ConnectionStrings__Default`; the Hostinger value is removed, not left alongside.
- **NetworkPolicy.** The tenant module already applies `default_deny_ingress`, so the Postgres
  pod rejects the API pod by default. Add an explicit allow from the app's pod selector to the
  cluster's on 5432. Deny everything else — nothing outside the namespace should reach it.
- Pin the Postgres major version explicitly, and record which one and why in
  `docs/homelab-infra/architecture.md`. "Latest" is not a version.

**Gate:** `psql` from a throwaway pod in the namespace connects; the same from another namespace
is refused.

**Watch for:** the resource quota in the tenant module was sized for an API pod alone. Postgres
needs its own headroom or the pod will not schedule, and the failure reads as a vague
`FailedScheduling` rather than anything about quota.

## Phase 2 — provider swap (`secret-santa-v2`)

> **Refined 2026-09-27 after reading the code.** Agreed with the owner; supersedes the bullets
> below where they differ.
> - **One options builder.** `UseSecretSantaPostgres(connectionString)` in `SecretSanta.Data`,
>   used by `Program.cs`, the design-time factory, the test fixture and `ApiFactory` — four
>   copies today, so tests stop exercising a lookalike of prod config. It forces
>   `Timezone=UTC` and `Maximum Pool Size=20` over whatever Terraform supplies (prod runs 2
>   replicas; Npgsql's default of 100 each exceeds CNPG's default `max_connections` of 100).
>   No retrying execution strategy: it throws on `GameService`'s user-initiated transaction.
> - **`UseCollation("utf8mb4_0900_ai_ci")`** in `SecretSantaDbContext` is model-wide
>   case/accent-insensitivity. Remove it, and audit string equality queries for reliance on it.
> - **`Database__ServerVersion`** goes from code and both configmaps.
> - **`DailyQuota`** stays raw SQL — EF has no upsert, and one atomic statement beats
>   insert/catch/update. Interpolated `SqlQuery<int>` (parameterized), `RETURNING counter AS
>   "Value"`, and `.AsAsyncEnumerable()` before `Single` so EF does not wrap the INSERT in a
>   subquery.
> - **`EmailOutbox`** catch narrowed to `UniqueViolation` **on `ux_msg_dedupe` by name**, via a
>   constant shared with the configuration. MySQL 1062 could not say which key; the old catch
>   would have reported any unique violation in the context as "already queued".
> - Postgres aborts a transaction on any failed statement; `GameService` enqueues inside one.
>   Safe because EF Core savepoints around `SaveChanges` in a user transaction — comment it.
> - Review `GameService`'s transaction for REPEATABLE READ (MySQL) → READ COMMITTED reliance.
> - **New tests:** no pending model changes; timestamptz round-trip `Kind=Utc` and
>   `Unspecified` throws; `SHOW TimeZone` = UTC via app DI; `/readyz` 200 and 503; startup
>   fails on bad connection string; `DailyQuota` parallel increments yield exactly 1..N;
>   non-dedupe unique violation in `EnqueueAsync` throws.


Measured, not estimated: 251 `HasColumnType` calls *(actually 51, recounted 2026-09-27)* in 6 files, 3 computed columns, 1 raw upsert,
1 exception check, 1 migration.

- **Packages:** `Pomelo.EntityFrameworkCore.MySql` → `Npgsql.EntityFrameworkCore.PostgreSQL`.
  Take EF 10 in the same move — the pin only existed because of Pomelo. Update
  `docs/ef-versions.md` in the repo, or delete it if it has no remaining purpose.
- **Wiring:** `UseMySql` + `MySqlServerVersion` → `UseNpgsql` in `Program.cs` and
  `DesignTimeDbContextFactory.cs`. Npgsql needs no server-version handshake object.
- **Types.** The mechanical bulk, with one judgement call running through it: **Postgres has no
  `unsigned`.**

  | MySQL | Postgres | Note |
  |---|---|---|
  | `tinyint unsigned` | `smallint` | Enum discriminators. Range decision per column. |
  | `smallint unsigned` / `int unsigned` | `integer` / `bigint` | Widen, or keep and add a CHECK. |
  | `datetime(3)` | `timestamptz(3)` | Decided 2026-09-27 — see below and `decisions.md`. |
  | `binary(32)` | `bytea` | Token and IP hashes. |
  | `char(26)` | `char(26)` | ULIDs. Unchanged. |
  | `json` | `jsonb` | `jsonb` is the right default. |
  | `date` / `time` | `date` / `time` | Unchanged. |

  On timestamps: **`timestamptz(3)`, entities stay `DateTime`, no legacy-behaviour switch.**
  Npgsql throws on non-`Utc` `DateTime` writes, so fix test/seed literals to
  `DateTimeKind.Utc` and add a round-trip test asserting `Kind=Utc`. Reasoning in `secret-santa-v2/docs/decisions.md`.

- **Computed columns:** drop the backticks — `(lower(trim(creator_email)))` and the two others.
  Postgres has supported stored generated columns since 12; the shape carries over intact.
- **`DailyQuota`:** `ON DUPLICATE KEY UPDATE counter = LAST_INSERT_ID(counter + 1)` becomes
  `ON CONFLICT (...) DO UPDATE SET counter = quota.counter + 1 RETURNING counter`. This gets
  *cleaner* — `LAST_INSERT_ID` was a MySQL workaround for the absence of `RETURNING`.
- **`EmailOutbox`:** `MySqlException { Number: DuplicateKeyErrorNumber }` →
  `PostgresException { SqlState: "23505" }`. Keep the named-constant style.
- **Migration:** delete `20260726030227_InitialCreate*` and the snapshot, regenerate. Safe only
  because no environment holds data. Confirm that is still true before deleting anything.

## Phase 5 — backup and the restore drill

- Scheduled base backup plus continuous WAL archiving to R2, both declared on the CNPG `Cluster`.
- Retention set deliberately. This dataset is tiny; a generous window costs nothing.
- **The drill, which is the actual deliverable:** restore `prod` into a scratch namespace from R2
  alone, at a point in time, and verify a known row. Write down how long it took and what the
  steps were — put that in `docs/homelab-infra/` runbook territory, because the person doing it
  next will be doing it under pressure.
- **Gate:** a completed restore, and a runbook entry someone could follow at 2am.

Monitoring belongs here too, but scoped down from the earlier plan: the WAN-address probe is now
pointless. What remains worth having is Cloudflare Tunnel health notifications (outside-in, no
code) and a dead-man's-switch ping so silence is noticed. The alerting path must not run through
Brevo, whose 90-day key expiry is itself one of the failures you want to hear about.
